# Доменная модель

> Статус: согласовано с владельцем (2026-10-18).

## Сущности

```
User 1──* Routine 1──* Habit
              │            │
              1            │
              *            │
         Occurrence 1──* HabitCheck *──1
```

### User
Многопользовательская модель: пользователь создаётся ботом при `/start` (chat_id должен быть
с доступом, D-020). В UI пользователь выбирается селектором (D-013).
- `id`, `telegram_chat_id` (unique), `display_name` (из Telegram), `timezone` (IANA), `created_at`

### Routine — группа привычек с общим расписанием
Именно рутина «звенит» и порождает одно сообщение-чек-лист. MVP: одна рутина «Утро» в 07:00.
- `id`, `user_id`, `title` («Утро»), `emoji`
- `schedule_kind`, `schedule_rrule`, `schedule_dtstart` — правило расписания (см. ниже)
- `next_run_at` (UTC) — служебное поле планировщика
- `is_active`, `sort_order`, `created_at`

### Habit — привычка
- `id`, `routine_id`, `title`, `description`, `emoji`
- `is_active` / `archived_at` (архив вместо удаления — история и серии сохраняются)
- `sort_order` (порядок в чек-листе)

### Occurrence — конкретный экземпляр рутины («Утро, 18 окт»)
- `id`, `routine_id`, `scheduled_for` (UTC), `local_date` (дата в TZ пользователя)
- `status`: `sent` | `missed` (worker не успел) | `closed`
- `closes_at` (UTC) — начало следующих локальных суток после `local_date`; до этого момента
  привычки можно отмечать (D-018)
- `telegram_message_id`
- unique(`routine_id`, `scheduled_for`)

### HabitCheck — отметка привычки в рамках occurrence
- `occurrence_id`, `habit_id`, `status`: `pending` | `done` | `skipped`, `checked_at`
- unique(`occurrence_id`, `habit_id`)
- Строки создаются для всех активных привычек **в момент создания occurrence** — это снимок
  состава чек-листа на тот день. Поэтому привычка, добавленная позже, не получает «прогулов»
  за дни до своего появления, а архивная — сохраняет историю.
- В Telegram нажатие на привычку циклически меняет статус: ⬜ `pending` → ✅ `done` →
  ⏭ `skipped` → ⬜.

## Расписания

Расписание принадлежит рутине и хранится как **RRULE (RFC 5545)** (D-007):
`schedule_kind = 'rrule'`, `schedule_rrule`, `schedule_dtstart`.
Время в правиле — **локальное время пользователя** (`User.timezone`).

| Паттерн               | RRULE |
|-----------------------|-------|
| Каждый день в 07:00   | `FREQ=DAILY;BYHOUR=7;BYMINUTE=0` |
| Будни в 07:00         | `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=7;BYMINUTE=0` |
| Выходные в 09:30      | `FREQ=WEEKLY;BYDAY=SA,SU;BYHOUR=9;BYMINUTE=30` |
| Каждые 3 дня в 07:00  | `FREQ=DAILY;INTERVAL=3;BYHOUR=7;BYMINUTE=0` (отсчёт от `DTSTART`) |
| Через неделю по пн    | `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO;BYHOUR=7;BYMINUTE=0` |
| 1-го числа месяца     | `FREQ=MONTHLY;BYMONTHDAY=1;BYHOUR=10;BYMINUTE=0` |

Расчёт: `dateutil.rrule` с `DTSTART` в TZ пользователя (`zoneinfo`) → следующее срабатывание
→ перевод в UTC для `next_run_at`. Для серий — перечисление назад (`before()`/`between()`).
API отдаёт и правило, и человекочитаемое описание («каждый день в 07:00»).
В диалоге бота расписание выбирается пресетами-кнопками, руками правило не вводится.

## Серии (streaks)

**Серия считается по запланированным occurrence, а не по календарным дням.** Иначе привычка
«по будням» рвала бы серию каждую субботу.

- **Текущая серия** привычки — число подряд идущих (от последнего к первому) occurrence её
  рутины, где у привычки `done`.
- Открытый occurrence (локальные сутки ещё не кончились) **не рвёт** серию (просто не
  добавляет +1, пока не выполнено).
- Закрытый occurrence без `done` (не отмечено или `skipped`) **рвёт** серию (D-014, D-018).
  `skipped` хранится отдельно только для статистики («пропустил осознанно» vs «забыл»).
- `missed` по вине системы (worker лежал, сообщение не ушло) — не рвёт и не продлевает серию.
- **Лучшая серия** — максимум за всю историю.
- Также для UI: процент выполнения за 7/30 дней, heatmap по дням.

Для MVP серии считаются на лету из `HabitCheck` (данных мало — сотни строк в год).
Кэш (`current_streak`, `best_streak` в таблице) — только если станет медленно.

## Milestones (пометки за длительное выполнение)

Подтверждено владельцем (D-017): значки за серии определённой длины.

Предлагаемые пороги (конфигурируемые): **7, 14, 21, 30, 66, 100, 180, 365**.
- 21 — популярная «точка формирования привычки», 66 — медиана из исследования Lally (2009).
- Показывать в UI: достигнутые значки + «до следующего: 5 дней».
- В Telegram: поздравление в момент достижения.
- Храним факт достижения (`HabitMilestone`: habit_id, threshold, achieved_on),
  чтобы значок не пропадал после обрыва серии («однажды достиг 30 дней»).

### ChatAccess — доступ к боту (D-020)
- `telegram_chat_id` (unique), `status`: `pending` | `allowed` | `denied`, `is_admin`
- `display_name`, `username` — из сообщения с заявкой
- `requested_at`, `decided_at`, `decided_by_chat_id`

## Сценарии MVP

1. Пользователь пишет боту `/start`, затем добавляет привычки интерактивной командой `/add`
   (для разработки — ещё `reminder seed`).
2. В 07:00 worker присылает чек-лист рутины «Утро».
3. Пользователь нажимает кнопки → отметки в БД → сообщение обновляется.
4. При достижении порога — поздравление.
5. UI (после выбора пользователя в селекторе) показывает: привычки, расписание, отметки за сегодня, текущую/лучшую серию, milestones.

## Команды бота (MVP)

| Команда    | Действие |
|------------|----------|
| `/start`   | Регистрация (если у чата есть доступ), установка TZ. Без доступа — заявка админам |
| `/today`   | Прислать чек-лист сегодняшнего occurrence заново |
| `/habits`  | Список привычек с сериями |
| `/add`     | Интерактивный диалог в одном редактируемом сообщении (aiogram FSM): название → выбор рутины кнопками или «➕ Новая рутина» (название + пресет расписания) → подтверждение |
| `/archive` | Архивировать привычку |

## API для UI (MVP, read-only)

Все `/api/v1/*`, кроме `/users`, работают в контексте пользователя из заголовка `X-User-Id`.

| Метод | Путь | Ответ |
|-------|------|-------|
| GET | `/api/health` | статус |
| GET | `/api/v1/users` | список пользователей для селектора |
| GET | `/api/v1/today` | рутины на сегодня, их привычки и статус отметок |
| GET | `/api/v1/routines` | рутины с расписанием (rrule + человекочитаемо) и привычками |
| GET | `/api/v1/habits` | привычки: текущая/лучшая серия, milestones, % за 30 дней |
| GET | `/api/v1/habits/{id}` | детали привычки |
| GET | `/api/v1/habits/{id}/history?from=&to=` | отметки по дням (для heatmap) |
